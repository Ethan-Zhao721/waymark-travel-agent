One shared HTTPS service can research destinations for every installed copy of the iPhone app. Deploy this directory together with the sibling Waymark/{Geography,MapNames,DestinationSources}.json, skills/xhs-travel-notes/scripts/city_boards.py and skills/waymark-destination/SKILL.md. Start with python3 destination-service/server.py behind a TLS reverse proxy. Configure OPENAI_API_KEY on the server for Xiaohongshu discovery. Configure GOOGLE_PLACES_API_KEY on the server for direct per-branch Google Places (New) lookup; without it, the worker checks cited Google Maps web sources. Mount persistent storage at WAYMARK_CACHE. HOST and PORT select the listener. WAYMARK_DAILY_LIMIT caps new research requests per day across all users.

The app distributor bundles a DestinationService.plist containing a baseURL string with the public HTTPS origin. The native itinerary shows up to ten sights and ten restaurants discovered from original Xiaohongshu notes. Mainland guides first check Amap citywide lists and the Dianping Must-Eat list and retain their distinct ranking conventions. International recommendations use regional discovery sources and need a verified Google Maps rating of 4.6 or higher and a review count. Restaurants need at least 300 reviews. The phone applies the same floor to older snapshots and shows qualifying Google-only picks separately. Without an endpoint the phone displays qualifying saved places and an explicit availability state. A dated city guide in the development phone’s Documents/guide-<cityID>.json can be previewed in existing and new plans. The public service reads the same guide format. Only the canonical city ID is sent to the service. Visits are private to each installation. The guides directory holds dated, researched data, separate from the app and from each user's visit history.

Every iPhone destination opens its native city itinerary, including a new city with no guide. In the restaurant sources tab, explicit buttons can open Google Maps, Xiaohongshu or the Dianping app. Empty and failed sight queries leave the itinerary accessible. The original platforms control their results and login requirements. The city itinerary keeps dated, verified guides and private check-ins separately.

For the native Google list, the distributor can add an `iosPlacesKey` string to `Waymark/DestinationService.plist`, enable Places API (New) in the billing-enabled publisher project and restrict the key to this iOS bundle identifier and the Places API. The phone automatically calls Text Search when the user opens the restaurant sources tab and keeps its results in memory. The request includes the destination name, country and city center. In the current sample it searches up to three pages within 12 km, filters to operating restaurants with at least 4.6 stars and 300 reviews, then shows up to six by review count. Real-credential acceptance and supplier billing must be verified by the publisher before release. An approved live data source for native Xiaohongshu and Dianping rankings is still outstanding.

A 202 response means the publisher service has recorded a city job in SQLite. The single server process owns its worker pool. Keep WAYMARK_CACHE on persistent storage so the service resumes accepted jobs after restart. The phone can close after submission and fetch the shared result when it reopens. Private check-ins stay on the traveler’s device. A fresh empty result is retried after the same cache window as a food guide.

The status response distinguishes queued, discovering and verifying. Status polling can stop while the phone is closed. A validated result replaces the guide atomically, and a transient upstream request can be retried twice. The foreground client resumes the saved query and keeps prior results during network loss.
