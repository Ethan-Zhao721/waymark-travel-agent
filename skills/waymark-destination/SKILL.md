# 城市打卡清单

用目的地的城市 ID、当地地名、英文名和国家查询公开资料。适用于所有新建和已有目的地。只需要目的地，无须旅行者的起点、实时位置、照片或平台账号。

1. 共用 Waymark/DestinationSources.json 按目的地国家或地区选来源。中国内地餐厅分别取高德全城美食原榜和大众点评同城必吃榜综合排序前十；国内景点取高德景点榜。保留完整名称、分店、年份、榜名、展示位置和链接，再对同一地点查小红书原帖。国内有已核榜单和小红书的卡片可直接展示。
2. 海外用米其林必比登和当地美食指南发现特色餐厅；日本加 Tabelog，景点用 Tripadvisor Travelers’ Choice 及当地旅游局、博物馆或景区官网。分开记录专业评选、游客口碑和官方事实。核对小红书原帖中的具体菜品、玩法和分店。
3. 海外餐厅和景点必须用相同分店或地点的 Google Maps 评分、评价数、原页和核对日期。保留现有推荐门槛：评分至少 4.6；餐厅至少 300 条评价，景点至少一条。地图、列表和计数使用同一批已核实地点；单来源 Google 候选另列。地址或名称有歧义时保留证据待核，不补数字。
4. 核价使用同店消费区间、分店菜单或有依据的人均，保留来源。perPersonUSDRange 保存折算后的美元上下限与用餐时段；无法核价则省略。套餐价不可当成人均。大众点评或餐厅官网可补价格，其他榜单只能作另外标注的参考。
5. 后台按城市 ID 持久化任务，重复打开复用同一查询。区分本机等待提交、服务已排队、搜索笔记、核对评分。只有服务确认接收后才能承诺关闭 App 仍继续。长查询期间保留上次核实日期和结果；全部验证通过后一次替换，返回前台自动取回，保留期间的手动打卡。短暂断网自动重试。iPhone 创建任意目的地后打开原生行程。查询中、无结果、缺少服务以及网络失败分别显示。只有用户主动点开原站才跳转。缓存仅展示有效证据；旧资料和既有访问记录可读取。原站搜索跳转不代表已取回榜单。

后台的小红书发现步骤调用 OpenAI Responses API 的 web_search，核对搜索工具返回的公开小红书原笔记链接。原站按钮仅以目的地关键词打开客户端或网页。验收时分别说明离线快照、站外检索结果和平台官方 API 的接入状态。

## 回归

分别验证两个不同城市、同名不同分店、重复链接、未观察到的原页、无点赞数的原笔记、缺评分或评价数、第十和第十一处，以及小红书和 Google 单来源在 4.5、4.6、299 和 300 条评价的边界。旧版小樽快照共十一家，验证六家进入高分榜（其中一家也有小红书笔记），其余五家缺评分保留在原缓存；一篇笔记可以推荐多家。检查地图和列表点位一致，旧 Wiki 景点与游览顺序不出现在城市推荐，手动打卡仍能回看。真机打开离线空城市应立即可交互；联网榜单另行用实际发布服务验证。

城市选择器需要用真实离线城市库回归连续输入、清空、中英文和城区归并。键盘输入期间不可在界面线程遍历和排序全库；已有地点的本地匹配与主动提交后的地图搜索分别验证。

景点空栏要区分从未联网检索、旧快照仅有美食、已收录景点笔记但缺合格 Google 数据，以及已完成检索却无可展示结果。原站搜索按当前城市和分类生成关键词，不能把景点入口固定成美食。用东京无指南和小樽餐厅快照同时验证。
